# v5.0.x 新功能（SPA 頁面解析支援 & 倉庫檢查升級）
- SPA 等動態渲染頁面的解析支援
- 倉庫檢查（倉檢）功能升級：多倉庫、倉庫預設、帳號密碼自動登入

---

## 功能說明
本次更新包含兩部分內容。

### 一、SPA 等動態渲染頁面的解析支援
部分網站在點擊其中的按鈕或連結時，會透過 JavaScript 動態渲染新內容，而不會觸發頁面的重新整理或重新載入。此時，舊版本的腳本將無法辨識新出現的 RJ 號，且容易殘留已經失效的連結節點。

目前版本已更新對這類頁面的解析邏輯，提高了對動態網頁的相容能力。若在使用時發現解析異常，請在回報中提供該頁面的 URL、瀏覽器版本與重現步驟等資訊，以便我們進一步改善。

### 二、倉庫檢查（倉檢）功能升級
已對倉檢功能進行大幅度升級，簡化了 kikoeru 倉庫的設定方式，並新增自訂預設以適配其他框架的倉庫。主要更新內容如下：

- **多倉庫**：最多可以新增**5 個倉庫**，可以同時啟用多個倉庫進行檢查，每個倉庫都會在彈出視窗中顯示一個獨立的搜尋結果標籤。
- **倉庫管理**：倉庫的新增、編輯、排序、啟停、刪除均可在獨立的倉庫管理介面中設定，設定介面大幅最佳化。
- **倉庫預設**：內建 `kikoeru` 預設，簡化原有的設定內容（支援帳號密碼自動登入）；新增**自訂預設**，用於適配其他框架的倉庫（詳見下文）。

**_由於倉檢方面更新內容較多，更新後請在設定頁中開啟倉庫管理，檢查原有的倉庫設定是否正確。若出現問題，請刪除原有倉庫並重新新增。_**

## 倉庫檢查的使用方法
### 開啟倉庫管理
1. 開啟設定：在瀏覽器中按右鍵，選擇 `Tampermonkey`（擴充功能名稱）→`VoiceLinks`（腳本名稱）→`Settings - 設定`。

![settings_open-context_menu.png](settings_open-context_menu.png)

也可以點擊瀏覽器右上角的 Tampermonkey 圖示，在展開選單中找到腳本名稱下方的設定按鈕。

![settings_open-addons_icon.png](settings_open-addons_icon.png)

2. 在設定頁中找到 `倉庫檢查` 分區，開啟 `開啟倉檢` 開關。

![settings_open-check.jpg](settings_open-check.jpg)

3. 點擊 `倉庫列表` 右側的「管理倉庫」按鈕，開啟倉庫管理彈出視窗。
4. 點擊右上角的「新增倉庫」，填寫倉庫資訊後點擊「新增」。

![settings_base-manage.png](settings_base-manage.png)

_將滑鼠移動到設定項標題上，即可查看該設定的相關說明_

_倉庫管理中的新增、編輯、排序、啟停、刪除都會**立即儲存並生效**；設定頁中的其他選項（`開啟倉檢`、`完整關聯`、`語言列表`、`連鎖查詢`）需要點擊設定頁底部的儲存按鈕。_

### 新增一個 kikoeru 倉庫
_請注意，該預設僅保證適用於 `number17/kikoeru` 的管理框架，其他類似分支可能可以使用，也可能需要使用自訂預設。_

在倉庫編輯介面中，`預設類型` 選擇 `kikoeru`，然後填寫：
- **倉庫名稱**：顯示在搜尋結果標籤前，多個倉庫可以重名。
- **倉庫地址**：倉庫的根地址，即平時存取倉庫用的連結，例如 `https://example.com`。
- **API 地址**：僅當倉庫的前端與 API 地址分離時才需要填寫（例如 API 使用了獨立的網域或連接埠），留空則使用上面的倉庫地址。
- **認證方式**：
  - `帳號密碼登入`：填寫倉庫的使用者名稱與密碼。腳本會在需要時自動登入並快取 token，token 失效時會自動重新登入。
  - `固定請求標頭`：用於無法使用帳號密碼登入的情境，需要在下方的 `自訂請求標頭` 中手動填寫驗證資訊（例如手動貼上的 token）。
  - `無認證`：倉庫無需驗證即可查詢。
- **自訂請求標頭**：一般留空即可。若倉庫 API 需要特定請求標頭（例如反向代理的驗證標頭）才能存取，可以在此填寫，格式為每行一個 `key:value`。

### 新增一個其他框架的倉庫（自訂預設）
在倉庫編輯介面中，`預設類型` 選擇 `自訂`。自訂預設透過「資料描述」來適配其他框架，可以填寫以下內容：

- **搜尋 URL 模板**：倉庫的搜尋 API 位址，其中的 `%s` 會被替換為搜尋關鍵字（RJ 號），例如 `https://example.com/api/search?keyword=%s`。
- **結果展示 URL 模板**：點擊搜尋結果標籤時開啟的位址，其中的 `%s` 同樣會被替換為 RJ 號；留空則點擊標籤不會開啟任何頁面。
- **請求方法**：`GET` 或 `POST`。
- **請求主體模板**（選擇 POST 時顯示）：送出的請求主體內容，其中的 `%s` 會被替換為 RJ 號，留空則送出空的主體，例如 `{"keyword":"%s"}`。
- **請求主體類型**（選擇 POST 時顯示）：`JSON` 或 `表單（x-www-form-urlencoded）`。
- **認證方式**：與 kikoeru 倉庫相同，可以選擇 `無認證`、`固定請求標頭` 或 `帳號密碼登入`。選擇 `帳號密碼登入` 時，需要額外填寫登入 API 位址、登入請求主體（`%username%` 與 `%password%` 會分別替換為使用者名稱與密碼）、登入請求主體類型、token 在回應中的取值路徑（例如 `token` 或 `data.token`），以及攜帶 token 的請求標頭（例如 `Authorization: Bearer {token}`）。
- **作品列表路徑**：回應 JSON 中作品列表所在的路徑（例如 `works` 或 `data.list`）。
- **作品識別欄位**：列表中代表作品的欄位名稱（例如 `id` 或 `workno`）。
- **作品識別轉換**：用於把作品識別對應到 RJ 號上：
  - `自動判斷`：回傳值是完整的 RJ 號時直接使用，是純數字時按數字比對。
  - `原樣作為作品編號`：回傳值必須是完整的 RJ 號。
  - `按數字比對`：忽略 RJ 號前綴，只按數字部分比對，適合只回傳數字 ID 的倉庫。

_若不知道搜尋 API 位址，可以透過瀏覽器的開發者工具（`F12`）→`網路（Network）` 分頁，在倉庫中搜尋一次 RJ 號，然後從請求列表中找到，具體步驟請參考[上一版文件](../v4.9.x/v4.9.x-zh_TW.md)中的說明。_

### 多倉庫時的搜尋標籤
每個**已啟用**的倉庫都會產生一個搜尋結果標籤，標籤內容為 `倉庫名: 結果文字`，標籤的排列順序與倉庫列表的順序一致。標籤的符號與顏色含義與上一版一致：
- 綠色：倉庫存在目前作品。
- 藍色：目前作品不存在，但存在目前作品的翻譯版本。
- 橘色：目前作品不存在，也不存在翻譯版本，但存在目前作品的原版。
- 灰色：目前作品不存在，也不存在任何其他關聯作品。
- 以 ⏳ 結尾：搜尋結果還沒有完全載入（邊搜尋邊更新）。
- 顯示為 ❌error：該倉庫載入發生錯誤。

**固定彈出視窗**時，點擊某個倉庫的標籤，會開啟**該倉庫**中所有存在作品的搜尋結果展示頁；如果該倉庫沒有找到任何作品，則會開啟本作 RJ 號在該倉庫的搜尋結果頁。

### 停用與刪除倉庫
- 關閉倉庫列表左側的開關即可**停用**該倉庫：停用後不會再向該倉庫發送任何請求（正在進行的連鎖查詢也會立即停止）。
- 點擊 `刪除` 將會刪除該倉庫的**全部設定資料**。
- 需要**暫時**排除某個倉庫時，建議使用停用而不是刪除，這樣設定會被保留。

## 設定項與其他 Q&A
設定項的說明請至設定頁中查看（將滑鼠懸停在對應設定項的標題上即可顯示說明），以下為常見問題與解答：

---

### 可以新增幾個倉庫？可以新增兩個同類型的倉庫嗎？
最多可以新增 5 個倉庫，達到上限後「新增倉庫」按鈕會變成無法點擊的狀態。此限制主要考量回應時間與安全性，避免同時向過多倉庫發送請求導致回應緩慢或被封鎖。如有需要可以從原始碼層面繞過。

同類型的倉庫可以新增多個（例如兩個 kikoeru 倉庫分別連接不同的伺服器），倉庫名稱也可以重複。

---

### 倉庫的前端與 API 地址分離，應該怎麼填？
在倉庫編輯介面中分別填寫即可：`倉庫地址` 填前端地址，`API 地址` 填 API 地址。兩者中任意一個留空時，腳本會使用另一個地址，因此只填一個也能正常運作。

---

### 為什麼某個倉庫的標籤顯示為 `❌error`？
出現 `❌error` 表示該倉庫這一次查詢失敗了，其他倉庫不受影響。排查步驟如下：
1. 使用 Ctrl 鍵固定彈出視窗（彈出視窗左下角會有提示文字），然後點擊發生錯誤的標籤，腳本會開啟該倉庫的結果展示 URL。
2. 如果結果展示頁面無法正常開啟，則可能是以下問題：
   - 網路連線錯誤
   - 倉庫地址填寫錯誤
   - 後文 Q&A 中提到的 HTTPS 問題
3. 如果結果展示頁面可以正常開啟，則可能是：
   - 該倉庫的認證設定有問題（認證方式、帳號密碼、token 請求標頭等填寫錯誤），可以嘗試在瀏覽器中重新登入倉庫，確認帳號是否可用
   - 自訂預設的解析設定與實際回應不符（作品列表路徑、作品識別欄位、作品識別轉換等）
   - 腳本錯誤（請根據後文所寫內容進行二次確認）

一般來說，如果出現 `❌error`，應該是該倉庫的所有 RJ 號都顯示 `❌error`。若有以下情況，則極可能是腳本錯誤，請提供搜尋的 RJ 號、發生錯誤的倉庫名稱與倉庫框架的版本資訊（作者／下載網址／倉庫網址）以便回報問題：
- 只對部分 RJ 號出現 `❌error`，其他 RJ 號均能正常查詢
- 搜尋結果展示到一半時突然變成 `❌error`

---

### HTTP 可以使用，但 HTTPS 會出錯？
可能是倉庫網站使用了非標準的憑證所導致，例如自簽憑證、憑證網域錯誤、憑證過期等等。

此時請**手動造訪一次倉庫網址**，瀏覽器應該會彈出警告（`net::ERR_CERT_COMMON_NAME_INVALID` 等類似的錯誤）。

點擊 `進階`，再點擊 `繼續造訪xxxxxx（不安全）`，正常進入一次網頁後，就可以正常使用功能了。

---

### 如何手動除錯？
**腳本問題：** 檢查（F12）的 `控制台（Console）`，看看有沒有來自 VoiceLinks 的 userscript 錯誤。涉及倉庫的錯誤訊息中會帶上發生錯誤的倉庫名稱，方便定位是哪一個倉庫的問題。

**網路問題：** 請查看 `Tampermonkey` 的 `background 頁面檢查`（在擴充功能管理裡，開啟開發者模式，然後找到 Tampermonkey，可以看到 `檢查視圖 background.html`，點擊 `background.html` 即可），在裡面的 `網路（Network）` 分頁中，可以查看腳本所有的網路請求資訊。

### 想適配新的倉庫框架
歡迎在 github 中回報，回報時請提供以下資訊：
- 倉庫的名稱、框架與版本（作者／下載網址／倉庫網址）
- 如果你是該倉庫框架的作者，也可以提供倉庫的 API 文件等資訊，以便更快地完成適配。
